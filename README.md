# Project-Update-AD-312-

Over the past several weeks, I've been contributing to the NSC Dev Expo Site project as part of my Application Development BAS practicum at North Seattle College.

The goal of the project is to build and improve a mobile-friendly React Native and Storybook component library that supports the NSC Dev Expo website. The project focuses on creating reusable, responsive UI components while following collaborative software development practices.

My role on the team has been contributing Storybook components, reviewing pull requests, testing implementations, and participating in the team's code review process.

### Work Completed

Over the last four weeks, I worked on several component-focused issues, including:

✅ Student Story Mobile Component (#131)

* Created a reusable Storybook component for the Student Story mobile page.
* Implemented configurable props to support different content variations.
* Tested and documented the component using Storybook.

✅ Information Section with Blocks (#110)

* Developed a reusable informational section component using existing project components.
* Reused and integrated StatBlock components to improve consistency and reduce duplication.
* Added Storybook support and responsive styling.

✅ Informational Section with Button (#106)

* Created a reusable informational section with dynamic title, description, and button props.
* Reused the existing HeroCTAButton component instead of creating duplicate functionality.
* Built Storybook stories for independent testing and documentation.

### Challenges & Solutions

One of the biggest challenges was learning the project's architecture and understanding how components, Storybook stories, and design requirements fit together.

Instead of immediately creating new code, I spent time reviewing existing components to identify reusable functionality. This helped me avoid duplicating code and reinforced the importance of modular design.

Another challenge was matching project conventions. Through pull request reviews and feedback from teammates, I learned the importance of:

* Keeping components reusable
* Using Storybook args correctly
* Avoiding hardcoded values
* Following established project structure and naming conventions

### Peer Reviews & Collaboration

In addition to development work, I reviewed multiple pull requests related to:

* Storybook components
* Responsive design
* Component reusability
* Figma design alignment
* Project architecture and maintainability

These reviews helped me better understand how collaborative development works and how code quality is maintained through peer feedback.
